# Preview: configuration window and live display

All upstream paths below are relative to `upstream/Vixen/src`. `VP/` is short for `Vixen.Modules/Preview/VixenPreview/`. `crate:` paths are under `crates/`. Reference JSON means `docs/reference/forms/Vixen.Modules__Preview__VixenPreview__*.json`. A bare `:N` in a citation means the file named most recently in the same sentence or bullet. With no file before it in the entry, it means the section's main file: `VP/VixenPreviewSetup3.cs` for the menu and toolbar entries, F35, F36, F51 and F100; `VP/VixenPreviewControl.cs` for the canvas entries and F52-F57; `VP/Shapes/MovingHeadIntentHandler.cs` for F121-F123.

**How to read this spec.** The geometry, hit testing, drag maths, selection state machine, undo stack, property rows, element linker, template store and custom prop builder are already ported in `crate:vixen-preview` as `DesignSession`, `Shape`, `ElementLinker`, `TemplateStore`, `build_custom_prop`. The GPU drawing and its thread are in `crate:vixen-render` as `LiveRenderer`. Live colours are in `crate:vixen-session/src/preview.rs`. So this spec concentrates on what is still missing: the two windows, the panels, the toolbars, the dialogs, the persistence around them, and the host wiring. Each feature says "Done in Rust" where a session call already does the work. Do not reimplement that logic in Swift.

**Project rule on oddities** (`docs/PORTING_GUIDE.md`): behaviour identical to Vixen, quirks ported as written, except that a C# exception must not become a crash. `DesignSession` follows that and marks each quirk "Deliberate". This spec states every quirk it found, and lists in "Quirks and decisions" (end of Features) the few where following the rule leaves a dead or harmful control, with a recommendation.

- [ ] **F23. Background group.**
  - **Set Background button** (`buttonSetBackground`, no tooltip in upstream, add `.help("Set Background")`). `buttonSetBackground_Click` (`VP/VixenPreviewSetup3.cs:271-288`). Open dialog with filter `JPG Files|*.jpg|PNG Files|*.png|GIF Files|*.gif|BMP Files|*.bmp|All Files|*.*`. **Copies the file** to the module data folder (`VixenPreviewDescriptor.ModulePath`, i.e. `VixenDisplayPreview`) under a new name `{guid}{ext}`, `File.Copy(..., overwrite: true)`. Sets `Data.BackgroundFileName`, `LoadBackground()`, sets the alpha slider to its maximum (255) and `Preview.BackgroundAlpha = 255`. No undo. The old file is left on disk.
  - **Background brightness slider** (`trackBarBackgroundAlpha`, 0...255, large change 10, ticks every 25). `ValueChanged` (`:573-584`): sets `Shape.BackgroundAlpha` on every display item, then `Preview.BackgroundAlpha = value` (which writes `Data.BackgroundAlpha`, rebuilds the alpha image, redraws). No undo. Initial value is `Data.BackgroundAlpha`, default 255 (`VP/VixenPreviewData.cs:28`).
  - **What alpha does** (`VP/VixenPreviewControl.cs:574-601`): a black rectangle is composited over the background. With a real image the black's alpha is `255 - BackgroundAlpha`, so 255 = full image, 0 = black. With the blank default background the black's alpha is `BackgroundAlpha`, which doesn't change anything visible since the bitmap is black. The rendered result is `image * (BackgroundAlpha / 255)`. In Metal that is a single uniform, no bitmap rebuild. ### Read and write sequence for one design session

1. Setup Previews stops the device if running.
2. Window opens: `load_preview_data` (from the effective store), `DesignSession::new(data, tree)`, `load_background_checked` with `set_background_file(None)` for anything but an image (F55, F56), `set_background_size` from the image or a blank size, `set_tool(Select)` (the upstream load does this, and it also sets `draw_shape` to empty), `set_clipboard_populated` from the app model, `setup_open()`, show `VerifyReport.message` if any.
3. During: `set_setup_bounds` on move and resize, `Change`s to the renderer.
4. File > Save: `location_updates` → `apply_location_updates`; write `data().to_xml()` into `system.module_store`; save system and module config off the main thread. Window stays open.
5. Close: invalid-link check (F4), fixture alert (F20), location updates, write data back, `previewDesignerClosed(id)`. Setup Previews restarts the device, and the live window reloads with the new data.

### `DesignerCanvas` (AppKit, required)

`final class DesignerCanvasView: NSView`, holding a `MetalLayerNSView` as its only subview, in an `NSScrollView` arrangement. `MetalLayerNSView` is `public final` (`app/Sources/VixenKit/MetalLayerView.swift:6`), so it can't be subclassed from this module as it stands; wrapping it also leaves the shared file alone, which `docs/UI_GUIDE.md` asks for. The subview must pass mouse events up, which an `NSView` does by default as long as it doesn't override them:

- An `NSScrollView` with overlay scrollers and an **empty** document view sized to `background size x zoom`. The Metal view is a sibling below it, sized to the clip view, not inside it, so the layer never scrolls or re-rasterizes. On `NSView.boundsDidChangeNotification` of the clip view: `designer.set_scroll(h, v)`, which moves the renderer's pan and nothing else. When `DesignerChange.scroll` arrives (zoom about pointer, middle-drag pan), call `clipView.scroll(to:)` guarded against the feedback. Flipped coordinates, top-left origin, because the session's are.
- Event overrides, each forwarding one FFI call: `mouseDown`, `mouseDragged`, `mouseUp`, `rightMouseDown`, `otherMouseDown/Dragged/Up` (middle pan), `mouseMoved` (tracking area with `.mouseMoved`, `.inVisibleRect`, `.activeInKeyWindow`; `acceptsFirstMouse` true), `keyDown`, `scrollWheel`, `magnify(with:)`, `flagsChanged` (session reads modifiers from each event; send a synthetic `mouse_move` on change so ⌘ constraints show at once). `acceptsFirstResponder` true, and `window.makeFirstResponder(self)` on every mouse down, or `keyDown` stops arriving once a property field has had focus (F27). No `rightMouseUp` to the session (F37). `mouseMoved` also carries a Multi-Point String or Multi-String between clicks (F29) and pasted shapes on the pointer (F32), so it can't be skipped when no button is down.
- Coordinates: points in clip-view space, rounded to `Int32`. The session and scene work in points, the renderer's `scale` handles Retina.
- Context menu: `menu(for:)` isn't enough because the C# builds it on mouse down after selecting. In `rightMouseDown` (and control-click), call `mouse_down(.right, ...)`, build an `NSMenu` from `context_menu` with the separators of F37, `NSMenu.popUpContextMenu`. Mac only: `Set Z Location to` is a real submenu.
- Cursor: `DesignerChange.cursor` maps `Default` → `NSCursor.arrow`, `Cross` → `.crosshair`, `Rotate` → a custom cursor from `VP/Resources/DoubleRotate.ico` (the C# resource `Rotate`), `InsertMode` → a custom cursor from `VP/Resources/InsertMode.ico`, `SizeAll` → a four-arrow custom image, since AppKit has none built in. Set on `cursorUpdate` too, so it survives focus changes.
- Text labels (F107) and the Elements highlight don't touch SwiftUI: labels are `CATextLayer`s in a sublayer reused by index.
- Drop target: `registerForDraggedTypes([.fileURL])`, `.prp` only (F57). Drop point converted through scroll as in `VP/VixenPreviewControl.cs:2673-2674`.
- `Overlay` and colours go from Rust straight to the renderer inside `PreviewDesigner`. No light data crosses to Swift.

### Live preview window
