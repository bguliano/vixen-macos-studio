# Vixen Studio MCP

## Status

Implemented: local bridge/in-app socket, shared live display undo, sequence authoring, real beat/bar analysis, inspection PNGs, contact sheets and MP4 preview videos, and FSEQ export. Only executable tools are advertised. The main UI branch must wire the new Studio FFI API into its panes. Legacy modal APIs remain compatible but must not be mixed with the live pane. This is not a claim of exhaustive native-editor parity; limitations are explicit below.

## Transport/process model

- vixen-studio-mcp --profile /absolute/profile speaks newline-delimited JSON-RPC on stdio. Logs stay off stdout.
- Prefer the profile-specific Unix socket under ~/Library/Application Support/Vixen Studio/. Directory 0700, socket 0600, same-user ownership, no symlink endpoints.
- Canonical-profile handshake prevents wrong-show attachment. Headless fallback needs a missing socket, or a provably ownerless one (see Stale-socket recovery). Broken, insecure or otherwise unproven endpoints fail closed.
- Headless takes Vixen's exclusive .lock; the app recognizes the lowercase bridge as a live owner. No stale-lock stealing. Headless is always muted and starts no app services.
- A headless bridge serves its muted core on the profile's socket too, so a second bridge or a script attaches to that session (same documents, sequence IDs and undo) instead of failing on the lock. The host stays up after its own client disconnects until the attached ones have too. `--persist` attaches the same way but, when nobody serves the profile, starts a background `--serve` session (stopped after 10 minutes with no clients) and attaches to it, so the session outlives any one client. `--serve [--idle SECONDS]` runs that session in the foreground (no idle limit by default) and refuses a profile already served. `call TOOL [JSON|-]` makes one tool call through the `--persist` route, prints the tool's text, and exits 1 with the tool's message on stderr when it refuses. A stop signal removes the endpoint, then the lock. `studio/python/vixen_studio.py` wraps `--persist` for scripts (see MCP-CLIENTS.md).
- VixenCore.start installs the server. Lower-level VixenCore.open is a test constructor; call studioStartMcp explicitly when using it. Shutdown rejects commands and drops the listener before releasing the profile lock.
- Max eight clients, 1 MiB requests, 8 MiB responses, 120-second idle reads, 30-second writes, bounded list pages. Same-user permissions are the trust boundary, not a sandbox against same-user malware.
- No HTTP listener, remote exposure, OAuth/token server or FPP network upload.

The synchronous adapter implements legacy MCP initialization (2024-11-05), tools, resources and prompts. Tasks, cancellation, subscriptions and HTTP are not advertised. The maintained official rmcp SDK (https://github.com/modelcontextprotocol/rust-sdk) was reviewed; it provides Tokio-based modern transport. The current adapter retains the app's threading model. Prefer rmcp before expanding protocol features.

## Commands and undo

vixen-session owns behavior; MCP adapts JSON-RPC. AppCore owns StudioDisplay, not a window. Display commands validate an isolated candidate through SetupSession algorithms, publish through AppCore::apply_display, then notify outside service/session locks. Failed commands do not partially publish.

Display, preview-prop, preview-list and show/schedule edits share one profile undo stack (20 full snapshots). Agent descriptions end in (Agent). Stable UUIDs identify elements/controllers/shows; preview prop IDs and schedule indexes require expectedRevision. Stale edits fail before mutation. Explicit profile save retains undo. Existing system/module serializers are separate writes; a second-write failure reports that the first succeeded.

Sequences use the same registered Arc<Mutex<SequenceSession>> and UndoStack as UI windows. A saved document's sequenceId is derived from its canonical file path, so every connection to the app gets the same ID for it, and it survives the app closing and reopening the file; an unsaved document's ID is its session ID until sequence_save, which returns the file's ID (the old one keeps working while open). Tools accept either ID; sessionId in the result is the session's own. sequence_open compares canonical paths and reuses the oldest session on the file, the one the app reuses; alreadyOpen:true means this core already had it open and the caller is now attached to that document and undo stack. sequence_open also takes an absolute path to a .tim file outside the profile, read in place (saves still go only into the profile), and reload:true, which discards this Studio session's copy and reads the file again under the same sequenceId (unsaved changes need confirm; refused while an app window holds it). sequence_open/create/status report file, path, modified and sharedWithApp: false from a headless bridge, whose muted core and unsaved documents the app never sees and which end with the bridge. studio_status mode is liveSession only when attached to the app. Agent effects/timing/parameters/layers/marks record native undo actions grouped with (Agent). StudioSettings adds reversible length/layer configuration. UI opening a saved agent document reuses the existing session; unsaved documents are obtained by sequence ID. Rendering uses the real engine schedule.

The show window's Display pane edits in a Display Setup working copy and publishes it with studioPublishDisplaySetup(session:expectedRevision:cleanup:): published exactly as a command's validated candidate is, one undo entry per publication (labels such as Edit Elements, Patching, Edit Controllers), refused when the display moved past expectedRevision or while non-muted execution is open (studioDisplayEditBlock). Legacy openDisplaySetup/commit/discard remains unchanged for compatibility. External/legacy display publication invalidates old Studio history on the next command rather than undoing unrelated edits. The new sidebar pane must use Studio commands/snapshots only.

## Swift integration contract

Generated VixenCore methods:

- studioDisplayCommand(command:argumentsJson:) -> JSON {changed,revision,result}; UI origin implicit. MCP supplies agent origin internally, never from JSON.
- studioDisplayCommandCatalog() and studioSequenceCommandCatalog() return exact schemas.
- studioDisplaySnapshot() -> {revision,elements,controllers}, fetched in bulk; studioDisplayHistory() returns newest-first undo/redo descriptions.
- studioSequenceCommand(command:argumentsJson:) calls the same authoring functions as MCP.
- studioOpenSequenceSession(sequenceId:) returns the shared SequencerSession for an agent-created/opened document.
- studioObserveDisplay(observer:) / studioStopObservingDisplay(): one observer per core. Callback occurs on a command thread, outside engine/session locks; dispatch to MainActor.
- studioDisplayEvents(afterRevision:) returns up to 100 events. Event revision is NOT the display revision used for expectedRevision.
- studioAgentSnapshot() returns authoritative clients, active tools and bounded recent outcomes; use on attachment/reconnect/gaps.
- studioStartMcp() throws on startup failure; studioMcpIsRunning() reports installed server state.
- studioStopMcp() drops only the listener (removing its socket) for exits that skip shutdown. The UI test harness calls it from `UITestHarness.beforeExit` before `quit` exits, so consecutive script runs on one profile each get a live server.
- studioAllowAgentsLiveOutput() / studioSetAllowAgentsLiveOutput(allowed:) are local-UI-only. Permission resets OFF each launch. Revocation stops agent-started controllers/test context. MCP has no setter.

StudioAgentActivity.observe(core:) is an @Observable MainActor adapter, built as a separate Swift module. It loads snapshots on attachment/callback, tracks clients/current tools/recent outcomes and exposes changedDocumentId. The coordinator owns toolbar/pane presentation. No existing Swift views were restyled here.

Events: clientConnected/clientDisconnected (command holds opaque client ID), commandStarted/commandFinished/commandFailed, displayChanged, documentChanged (documentId), profileSaved, outputChanged. No arguments/audio paths in activity events. Preview edits set the existing preview reload flag. Refresh bulk pane snapshots on changes, never per row.

## Implemented surfaces

- Profile/status: identity/version/safety, sequence/media inventory, confirmed save. Profile selection is a launch argument, not silent app switching.
- Display: elements/groups CRUD, native single/arch/group/megatree/matrix templates with an optional colour (rgb/rgbw/single) applied in the same step, megatree/matrix wiring shared with the template sheet's live diagram (`studio_wiring.rs`: start corner on a drawing with S1 on the left and Px1 at the bottom, reverseEveryOtherString, hiddenPixels at each string's Px1 end kept in a separate "<name> Hidden" group that keeps its wire position; every light gets its wire position as its Order, and patch_elements patches in that order, with alsoIds to include the hidden group in the same run), element_color colour handling (rgb: 3 channels per pixel, rgbw: 4 in R, G, B, W order, single: 1; the Color Handling helper's property and breakdown filter, so patching connects every channel), reverse wire order, patching by intent (patch_reverse reverses an element/group's light order on its own outputs, patch_swap trades two equal-sized elements' outputs, patch_move moves them in order to free outputs from startOutput, patch_ranges reads where it is; each light keeps its channels in order, results give universe:channel ranges, and the Display pane's element context menu runs the same commands under Patch), undo/redo.
- Controllers: types/list/create/rename/delete, patch/unpatch, monitor, separately gated start/stop/test pattern. Commissioning tests (`studio_commission.rs`, the Display pane's Test submenu on an element, group or controller): output_test_pattern pattern movingPixel (one light at a time in wire order: an element's patched lights by first output, then unpatched ones; a controller's by output), colorBars (every light red, green, blue, white; one shared per-step colour array however many lights) or allOn, at brightnessPct (default 25), played in a live context with no sequence for durationMs (agents default 60 s, the UI until stopped, both at most 10 minutes); one test at a time, output_test_stop or Stop Test ends it at once, and closing Live Output ends it. The UI needs Live Output on; agents also need the permission switch. While Live Output pauses display editing, the pane's trees stay browsable with a read-only menu (Patch ranges and Test) and every editing control is disabled. controller_configure is the controller inspector's command: protocol (E1.31/DDP; changing it replaces the controller, keeping name, outputs and patches, and returns newId), IPv4 unicast address, output count, first universe and channels per universe (510/512, or preset wledRgb/wledRgbw), with universes generated from the output count; omitted fields keep their values. controller_network reads the same settings, pixel counts, presets and status (running, packets sent, last packet); check:true tests whether the address answers on TCP port 80 (no lighting data), refused while muted.
- Previews (the show window's Previews pane, `studio_previews.rs`): preview_create (an empty preview, on, named "New Preview" or numbered), preview_rename, preview_duplicate (the whole layout and links, after the original, "<name> copy"), preview_delete (confirm; Undo brings it back) and preview_enable (on = not in DisabledDevices, so it shows whenever Live Output is on). Each is one step on the shared history, labelled in words ("Delete Preview (Agent)"), and they publish without apply_display: nothing playing stops, no controller restarts, and they stay open to agents while Live Output is on. Undoing a display step still needs Live Output off; history reports undoPreviewOnly/redoPreviewOnly. preview_list adds enabled. The designer's write-back when it closes is also one step, "Edit Preview Layout", when the layout changed (refreshed light locations alone add none).
- Preview: preview IDs/linked nodes, native prop/property inventory, common shape creation, primitive property edits, element linking, inspection PNG. A megatree, matrix or arch can be shown in a preview already linked (`studio_props::add_linked`): element_template previewId does it for a new prop in the same undo step, preview_prop_create elementId for an existing element, and the template sheets' Show in Preview picker runs the same code. The designer builds the shape from the element as when a prop is drawn with it selected (strings, lights per string, every light's link in element order, 360° for a megatree), sized for its lights and placed right of the preview's other props; an element it can't take light for light (a megatree under 4 strings of 5 lights) is refused and nothing changes. preview_video renders a span (default the whole sequence, 25 fps) to one H.264 MP4 under Export, with the sequence audio for that span as AAC, through AVFoundation, so no ffmpeg and no per-frame files; a 2:46 song (4,155 frames, 1,019 lights, glow on) takes about 38 s. preview_sheet tiles a span into one PNG, each frame captioned with its m:ss.cc time (default 2 fps, 8 columns, 160 px tiles, at most 400 tiles), for reviewing a passage as one image. Both hold the sequence lock only to render effects and take the schedule, so the editor stays responsive while frames are painted; audio a file AVFoundation cannot decode is reported under `audio.omitted` and the video is written without it.
- Sequences: create with audio/open/status/save/length/clear/close; effects list/add/delete/timing/copy/parameters; layers list/create/rename/delete/assignment; marks/undo/redo/render; guarded play/pause/stop/seek.
- Bulk authoring: effect_add takes params and layerId inline, and several targets at once: targetIds (one effect per target) or targetSlice, a group's children picked by position ({groupId, strings:[from,to], every, offset}, e.g. alternating halves of a tree) without adding a group to the display; all of one call's effects undo together. effect_band (and the batch band op) holds a still horizontal band from fromPct to toPct of the targets' height, counted from the bottom, as a native Wipe (Vertical, Movement mode, flat MovementCurve at 100·to/(100+width), pulse as wide as the band), so the band opens in the effect editor and in Windows Vixen like any Wipe; its edges land on the nearest preview row; its level is constant over the effect, and like any Wipe it lights only elements with Vixen's Location property. effects_batch applies add/delete/timing/params ops as one undo step (consecutive adds and deletes each undo in one pass) with one render pass; every op is validated before anything changes, and an invalid op fails the batch naming its index. Ops come inline or from opsFile, a .json path relative to the profile folder (no `..`, absolute paths or symlinks; up to 100,000 ops and 64 MiB), since a whole show exceeds the 1 MiB request limit. Measured: 6,000 Pulse adds with a level curve each apply in about 0.7 s. sequence_clear deletes every effect as one undo step. sequence_save scratch:true writes to Sequence/.scratch, which the app's sequence list never shows, for throwaway builds and previews; backup:false overwrites without the auto_backup copy. sequence_close releases a document this Studio session created or opened; one the app has open in a window stays open there, and discarding unsaved changes needs confirm.
- Music: native beat/bar tracker (deduplicated beats), tempo estimate, 100ms RMS energy, per-band spectral-flux onsets (low/mid/high, millisecond times with strength, bar and 16th slot) plus a per-bar slot-strength grid, and a labelled section-change heuristic. Authored phrase/word/phoneme marks supported. sequence_onset_marks writes the onsets into the sequence as mark collections, one per band ("Onsets - low/mid/high"), each mark's text its strength, so the rhythm is visible on the timeline and can be hand-edited; undo empties them (undo never removes a collection, as with the native marks panel). effects_on_marks places one template effect (effect_add's fields) on every mark of a collection in one undo step: optional range, minStrength, snap to the beat/8th/16th of a beat collection (default "Music - All") with same-point marks merged to the strongest, duration "untilNext" × gapFraction (default 0.8) or fixed milliseconds with a maxMs cap, levelFromStrength (scales LevelCurve, Curve, PulseCurve or IntensityLevel through levelRange), rotateTargets (one target per mark in turn) and cycle (a parameter's values in turn per mark, e.g. colours). A mark whose text is not a number counts as strength 1. effect_step builds a discrete staccato figure in one undo step, stepped on a mark collection or a stepsMs list: walk (width segments step one per hit), alternate (even/odd segments, so count 2 is front/back halves), stack (bands accumulate from the bottom and cut together) or jump (seeded positions, never the previous hit's); segments are a group's children split into count runs (native Set Level per child) or count horizontal bands of the targets (band Wipes as effect_band); colours cycle per hit, holdFraction keeps staccato gaps and cutAtMs ends the run. The figure is ordinary native effects, so it opens in the effect editor and Windows Vixen.
- Shows/schedules (the show window's Schedule pane, `studio_schedule.rs`): show_create (empty, or with sequences), show_rename, show_duplicate, show_delete (confirm; a show that schedules run needs deleteSchedules:true, deleting them in the same step), show_item_add/update/move/delete (a sequence, a .tim file under Sequence, or a 1-900 s pause, in a section: startup, sequential, background or shutdown, counted from 0 in run order), schedule_create (show, first and last day, start and end time, days Sunday first; off unless enabled:true), schedule_update, schedule_enable, schedule_duplicate (the copy off) and schedule_delete (confirm). Schedules are addressed by index with expectedRevision. Each is one step on the shared history, labelled in words ("Turn On Schedule (Agent)"), published without apply_display (open to agents while Live Output is on), and handed to the running scheduler at once; Undo restores schedules but leaves the scheduler's own switch alone. show_list gives each show's steps by section; schedule_list adds state (off, upcoming, due, playing, ended, never), nextRun and the scheduler's status line. Turning the scheduler itself on (Scheduler ▸ Enabled) is the user's switch: no tool does it, so nothing an agent schedules plays until the user has it on. Launch steps (running programs) are listed but never created or edited; no remote activation.
- Diagnostics: unpatched elements, unused outputs, invalid patches/configurations, overlapping universes, open-sequence missing media/targets/native color corrections, bounded log tail, actual engine/controller state.
- Export: confirmed local uncompressed FSEQ v2 at 50ms; no upload.
- Geometry: display_geometry reports, per linked light, its preview (x, y) (preview_frame's space at scale 1), 0-100 xPct/yPct within its prop (y from the bottom) and its string and pixel numbers, counted from 1 in element order as targetSlice counts them (S1 Px1 = string 1 pixel 1). Megatrees add heightPct along the string and angleDeg around the trunk (0 front, 90 viewer's right, 180 back, 270 viewer's left, seen from above), arches positionPct. Each prop's summary names its type and size, where Px1 sits (megatree bottom/top, arch left/right, matrix corner), S1's angle and position, and whether string numbers run clockwise or counter-clockwise seen from above (matrix: which way a string runs and where the next one starts). Filter by previewId and/or elementId; pixels:false gives summaries only. Angles come from the megatree's own layout (string count, coverage degrees, degree offset), measured on the prop's own base ellipse before any Rotation Angle.
- Command palette: command_palette searches the running app's menu commands as the ⌘K palette does (`studio_palette.rs`): menu path, shortcut, enabled and the reason when not, and agentTool, the MCP tool that does the same thing. The app publishes its live menu bar per front window (show or sequencer) each time the palette opens, so the tool answers for what the user last saw; a headless bridge has no menu bar and says so. Read-only: agents never run menu commands through it.
- Resources studio://contract and display://summary (every prop's geometry summary, to read once at the start of a session), and the build_show workflow prompt.

Shared structural schema validation enforces types/required fields/ranges, followed by native domain validation. Effect parameter schemas (effect_catalog, effect_parameters) give each numeric parameter the stored-value minimum/maximum its native editor allows, converted through the property's getter/setter (the same range effect writes enforce; editors without one report the 100000 safety limit), a unit where known (milliseconds, fraction), the native default, and name the color shapes colorList, gradient (flat #RRGGBB list) and gradientList (list of those). A multi-color gradient is written with evenly spaced stops. Raw XML parameters are never accepted. Strings/lists/numeric work are bounded.

## Safety

Delete/unpatch/save/overwrite/export and output commands require explicit confirmation. Default-off local output permission cannot be changed by MCP. VIXEN_MUTE overrides startup/test/transport. Headless always stays muted. Agents cannot implicitly open execution and start every controller: open execution locally first; output_start addresses one E1.31/DDP controller. output_stop and output_test_stop remain usable after permission revocation, which also ends an agent's test.

Display edits are rejected while non-muted execution is open because graph publication may restart controllers. Edits to a live non-muted sequence require stopping it first. Non-muted playback/seek requires local permission and confirmation. Analysis/render/export never plays sound or sends controller packets.

Writes stay within selected-profile Sequence/Export/config directories. Filename-only outputs, canonical parent checks, symlink rejection (including backup/temp trees), and exclusive save temporary files protect the original archive. Media may be a read-only symlink; no tool writes Media. The bridge refuses the known original-show archive. Tests use disposable copies and VIXEN_MUTE=1, never real output.

## Known limits

- No automatic lyrics transcription/phoneme alignment. Bars assume 4/4. Section candidates are an energy heuristic, not semantic song structure; onset times are estimates, typically within 10 ms.
- PNG uses real geometry/links/schedule/color conversion but CPU inspection rasterization: no background artwork, fixture beams or GPU antialiasing; max 2048 dimensions. Videos and sheets use the same rasterizer; glow adds a soft additive halo, not the app's GPU bloom.
- Common primitives/enums/colors/RGB/curves/gradients/gradient-level pairs ({gradient, curve} lists, e.g. Alternating, Pinwheel and Dissolve Colors)/nested records supported; effect_catalog and effect_parameters add a `note` where a parameter needs more than its native label (GroupLevel/EnableDepth/DepthOfEffect on Alternating and Dissolve). Font, raw XML and file-path parameter selectors remain rejected with rejecting schemas. Layer creation currently uses highest-value mixing.
- Controller editing covers IPv4 unicast with generated universes, not every serial/specialist dialog or manual multicast/universe layout (the Advanced… dialog). "Last packet" is as fresh as the caller's polling (the engine counts packets but keeps no clock). Real hardware startup/test is deliberately untested.
- No program-launch show steps or silent profile switching; the scheduler's on switch stays local.
- An open designer holds its own working copy and writes it back when it closes (one undo step), over agent preview_prop edits made to that preview meanwhile. The Previews pane holds Undo and Delete for a preview while its designer is open.
- Undo is bounded by count, not bytes; huge profiles may be memory-intensive. Audio analysis: 100 MiB input/15 minutes. Templates: 4096 leaves. Long tasks have no MCP cancellation yet.
- A connection idle for 120 seconds is closed, including a bridge attached to the app or to another bridge's session; scripts reconnect (vixen_studio.py does so once per call). An MCP client that sits idle longer should be the session's host (plain `--profile`, started before any script), not `--persist`.
- A socket left by a crash or force-quit is recovered automatically under the rules below. One that fails them (wrong owner or mode, a symlink, something answering, or a profile lock this process doesn't hold) still blocks the server; the log names the file.

## Stale-socket recovery

A crash or force-quit leaves the endpoint behind. `socket::recover_stale` removes it only when it provably has no owner, and never touches the profile `.lock`:

1. This process holds the profile's exclusive Vixen lock (`lock_held_here`: `.lock` is a regular same-user file naming this pid on this machine). The app takes it at startup, before the server starts. Lock taking itself is unchanged: a dead process's lock is cleared only by vanilla's existing `IsProfileLocked` check.
2. The directory and socket pass `secure()`: same uid, directory 0700, socket type, mode 0600, no symlinks.
3. `connect()` returns `ECONNREFUSED`. A connection means a live server and is left alone; any other error is returned.
4. The device and inode still match what was inspected; the path is unlinked once and bound again. No retry loops.
5. One warning is logged: `[Vixen.Studio.MCP] Removed stale MCP socket <path> (no listener; profile lock held)`.

The app runs this when `bind` reports `AddrInUse`. The bridge runs it when its connection is refused: it first creates the lock, which fails if any lock file exists, stale or not, then recovers, releases the lock and serves headless. So a bridge never clears a crashed app's lock; relaunching the app does that and recovers the socket.

Verified: unit tests for each rule (`cargo test -p studio-mcp --lib stale_tests`); on a show copy, force-killing the app left the socket and lock, a bridge then failed closed, relaunching logged one removal and served the live session, and with no app and no lock the bridge recovered the endpoint and served headless.
